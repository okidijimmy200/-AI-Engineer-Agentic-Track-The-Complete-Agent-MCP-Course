# Lecture Note: 16. LLM as a Judge (with Code Integration)

## Introduction

This lecture concludes Lab 2 by introducing the **LLM as a Judge** pattern. After generating a challenging question with a flagship model and obtaining diverse answers from nine different LLMs, we now delegate the evaluation process to a separate, high-tier model. This approach is a cornerstone of agentic AI, where multiple model calls are orchestrated to improve the quality, resiliency, and objectivity of the final output.

## I. Pythonic Orchestration: Iteration and Anonymization

To prepare the data for the judging model, we use standard Python techniques to organize our lists of competitors and their corresponding answers.

### A. Efficient Iteration with `zip` and `enumerate`

The `zip` function allows for simultaneous iteration over multiple lists, while `enumerate` provides both the index and the value of each item.

**Example 1.1: Iterating through Competitors and Answers**

```python
# Using zip to pair competitors with their answers
for competitor, answer in zip(competitors, answers):
    print(f"Competitor: {competitor}\n\n{answer}")

# Using enumerate to track indices
for index, answer in enumerate(answers):
    print(f"Index {index+1}: {answer}")
```

### B. Anonymizing Responses to Avoid Bias

To ensure the judge evaluates the *content* rather than the *brand* of the model, we anonymize the responses by labeling them "Competitor 1" through "Competitor 9."

**Example 1.2: Constructing the Anonymized Dataset**

```python
together = ""
for index, answer in enumerate(answers):
    together += f"# Response from competitor {index+1}\n\n"
    together += answer + "\n\n"

print(together)
```

## II. The Judging Pattern: Prompting and JSON Output

The "LLM as a Judge" pattern involves framing the evaluation task as a structured prompt, often requiring the judge to respond in a machine-readable format like JSON for easier downstream processing.

### A. The Judge's Prompt

The prompt defines the judge's role, the evaluation criteria (clarity and strength of argument), and the required output format.

```python
judge_prompt = f"""
You are judging a competition between {len(competitors)} competitors.
Each model has been given this question:

{question}

Your job is to evaluate each response for clarity and strength of argument, 
and rank them in order of best to worst.

Respond with JSON, and only JSON, with the following format:
{{"results": ["best competitor number", "second best competitor number", ...]}}

Here are the responses from each competitor:

{together}

Now respond with the JSON with the ranked order of the competitors, nothing else.
"""
```

### B. Executing the Judgement with Grok

For the role of the judge, we select **Grok 4.3**, branded as a "truth-seeking" model. This choice highlights the strategy of using a powerful, independent model for critical decision-making tasks.

```python
from openai import OpenAI
import os

# Initialize Grok client (using OpenAI-compatible endpoint)
grok = OpenAI(api_key=os.getenv('GROK_API_KEY'), base_url="https://api.x.ai/v1" )

model_name = "grok-4.3"
judge_messages = [{"role": "user", "content": judge_prompt}]

response = grok.chat.completions.create(model=model_name, messages=judge_messages)
results_json = response.choices[0].message.content
print(results_json)
```

## IV. Agentic Design Patterns and Commercial Implications

This lab demonstrated a **Hybrid Agentic Pattern**, combining elements of:

1. **Orchestration**: Chaining multiple LLM calls (Question -> Answers -> Judge).

1. **Parallel Execution**: Farming out the same task to multiple models.

1. **Self-Correction/Evaluation**: Using an LLM to verify and rank the work of others.

### Commercial Applications

- **Resiliency**: By using multiple providers, you avoid single-point-of-failure risks.

- **Quality Assurance**: Automated judging allows for high-volume, objective quality control in customer support, content generation, or data extraction.

- **Cost Optimization**: You can use cheaper models for bulk work and reserve expensive models for high-stakes judging.
