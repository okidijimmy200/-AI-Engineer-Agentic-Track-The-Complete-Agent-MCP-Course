# Lecture Note: 14. OpenAI Compatible API (with Code Integration)

## Introduction

In the rapidly evolving landscape of Large Language Models (LLMs), a significant trend has emerged: the standardization of API endpoints. While many providers initially launched proprietary APIs, the industry has largely converged on the **OpenAI-compatible API** format. This lecture explores how to leverage this compatibility to orchestrate multiple models from diverse providers—including Anthropic, Google, DeepSeek, and local models via Ollama—using a unified client library.

## I. The Concept of OpenAI Compatibility

OpenAI compatibility means that a provider's endpoint expects requests in the exact same format as the OpenAI API (a list of message dictionaries with roles and content). This is highly convenient for AI engineers as it allows for:

- **Unified Tooling**: Using the same Python client library (`openai`) for multiple providers.

- **Seamless Switching**: Changing providers by simply updating the `base_url` and `api_key` without rewriting the core logic of the application.

- **Local vs. Cloud Flexibility**: Switching between local models (e.g., via Ollama) and cloud models (e.g., OpenAI) with minimal code changes.

## II. Multi-Provider Configuration

To orchestrate multiple models, we first define the base URLs for each provider's OpenAI-compatible endpoint.

### A. Defining Base URLs

```python
# OpenAI Compatible URLs for various providers
ANTHROPIC_BASE_URL = "https://api.anthropic.com/v1/"
DEEPSEEK_BASE_URL = "https://api.deepseek.com/v1"
GEMINI_BASE_URL = "https://generativelanguage.googleapis.com/v1beta/openai/"
GROQ_BASE_URL = "https://api.groq.com/openai/v1"
GROK_BASE_URL = "https://api.x.ai/v1"
OPENROUTER_BASE_URL = "https://openrouter.ai/api/v1"
OLLAMA_BASE_URL = "http://localhost:11434/v1"
```

### B. Instantiating Provider Clients

We instantiate multiple instances of the `OpenAI` class, each configured with the appropriate `base_url` and the corresponding API key from our environment variables.

```python
import os
from openai import OpenAI

# Instantiating clients using the OpenAI class
anthropic = OpenAI(api_key=os.getenv('ANTHROPIC_API_KEY' ), base_url=ANTHROPIC_BASE_URL)
deepseek = OpenAI(api_key=os.getenv('DEEPSEEK_API_KEY'), base_url=DEEPSEEK_BASE_URL)
gemini = OpenAI(api_key=os.getenv('GOOGLE_API_KEY'), base_url=GEMINI_BASE_URL)
groq = OpenAI(api_key=os.getenv('GROQ_API_KEY'), base_url=GROQ_BASE_URL)
openrouter = OpenAI(api_key=os.getenv('OPENROUTER_API_KEY'), base_url=OPENROUTER_BASE_URL)
ollama = OpenAI(base_url=OLLAMA_BASE_URL, api_key="ollama") # Ollama uses a dummy key
```

## III. The Multi-Model Intelligence Challenge

The lab demonstrates a "competitor" framework where multiple models are asked the same complex question generated by a flagship model (e.g., GPT 5.5).

### A. Utility for Tracking Answers

To manage the responses from various models, we implement a simple tracking system.

```python
from IPython.display import Markdown, display

competitors = []
answers = []

def record(model_name, answer):
    competitors.append(model_name)
    answers.append(answer)
    display(Markdown(f"### {model_name}\n{answer}"))
```

### B. Executing the Challenge Across Models
