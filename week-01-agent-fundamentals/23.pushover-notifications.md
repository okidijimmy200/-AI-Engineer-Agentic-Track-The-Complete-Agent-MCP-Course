# Lecture Note: 23. Pushover Notifications (with Code Integration)

## Introduction

In this lecture, we enhance our Digital Twin by adding real-time monitoring capabilities. We introduce **Pushover**, a simple and effective service for sending push notifications directly to mobile devices. By integrating Pushover, our agent gains the ability to alert us when a potential client is interested in getting in touch or when it encounters a question it cannot answer. This is a practical example of how agents can interact with the physical world through APIs.

## I. Setting Up Pushover

Pushover is a lightweight notification service that requires two specific keys for authentication.

### A. The Two-Key Authentication System

1. **User Key**: A unique identifier for your Pushover account (starts with the letter `U`).

1. **API Token**: A key generated for a specific application you create within Pushover (starts with the letter `A`).

### B. Environment Configuration

These keys should be stored securely in a `.env` file to avoid hardcoding sensitive information.

```bash
# .env file configuration
PUSHOVER_USER=Uxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
PUSHOVER_TOKEN=Axxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

## II. Implementing the Notification Tool

The technical implementation involves a simple HTTP POST request to the Pushover API.

### A. The `send_pushover` Function

This function takes a message string and sends it to the user's phone via the Pushover service.

```python
import requests
import os

def send_pushover(message):
    """Sends a push notification to a mobile device via Pushover."""
    user_key = os.getenv("PUSHOVER_USER")
    api_token = os.getenv("PUSHOVER_TOKEN")
    
    url = "https://api.pushover.net/1/messages.json"
    data = {
        "token": api_token,
        "user": user_key,
        "message": message
    }
    
    response = requests.post(url, data=data )
    if response.status_code == 200:
        print(f"Notification sent: {message}")
    else:
        print(f"Failed to send notification: {response.text}")
```

## III. Equipping the Digital Twin with Notification Tools

We define two specific tools that utilize the `send_pushover` function to provide the agent with real-world agency.

### A. Tool 1: `record_interest_tool`

Used when a visitor wants to get in touch. It captures the email, name, and any additional notes.

```python
def record_interest_tool(email, name=None, notes=None):
    message = f"New Interest!\nEmail: {email}\nName: {name}\nNotes: {notes}"
    send_pushover(message)
    return "Interest recorded successfully."
```

### B. Tool 2: `record_unknown_question`

Used when the agent encounters a question not covered in its context. This allows the developer to identify gaps in the agent's knowledge.

```python
def record_unknown_question(question):
    message = f"Unknown Question: {question}"
    send_pushover(message)
    return "I have noted your question and will let my creator know."
```

## IV. Describing Tools with JSON Schema

To enable the LLM to use these tools, we must provide detailed JSON descriptions. This "janky JSON" is what agent frameworks typically automate, but writing it manually ensures a deep understanding of the underlying protocol.

**Example 4.1: JSON Schema for ****`record_interest_tool`**

```python
record_interest_tool_json = {
    "name": "record_interest_tool",
    "description": "Use this tool to record that a user is interested in being in touch.",
    "parameters": {
        "type": "object",
        "properties": {
            "email": {"type": "string", "description": "The user's email address"},
            "name": {"type": "string", "description": "The user's name (optional)"},
            "notes": {"type": "string", "description": "Additional information (optional)"}
        },
        "required": ["email"],
        "additionalProperties": False
    }
}
```

## V. Biasing Agent Behavior through Prompting

LLMs can sometimes be reluctant to use certain tools (like the `unknown_question` tool).

- **Prompt Iteration**: Use strongly worded descriptions like "Always use this tool..." in the JSON schema.

- **Token Likelihood**: By refining the prompt, we increase the statistical probability that the model will generate the tokens required to trigger the tool call.
