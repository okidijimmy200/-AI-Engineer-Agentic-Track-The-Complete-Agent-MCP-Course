# Lecture Note: 18. How Tool Calling Works (with Code Integration)

## Introduction

Tool calling, also referred to as **function calling**, is the foundational mechanism that transforms a Large Language Model (LLM) from a simple text generator into an **autonomous agent**. While LLMs are inherently limited to predicting the next most likely token in a sequence, tool calling allows them to interact with the external world—querying databases, searching the internet, or manipulating software—by generating structured instructions that external code can execute.

## I. The "Boring Truth" of Tool Calling

A common misconception is that an LLM "reaches out" and executes code on a user's computer. In reality, the process is far more discrete and relies on standard programming logic.

### A. The Magical Perception vs. The Technical Reality

- **Perception**: The LLM autonomously identifies a need, searches for a tool, and executes it.

- **Reality**: The LLM is provided with a description of available tools. It generates tokens (often in JSON format) indicating its *intent* to use a tool. The **developer's software** is responsible for reading those tokens, executing the actual function, and returning the result to the LLM.

### B. The Value of the LLM in the Loop

If the developer's software is doing the actual work, why involve an LLM? The answer lies in **Natural Language Understanding (NLU)**.

- **Intent Mapping**: An LLM can recognize that "How much does it cost to go to Paris?" and "Get the price for a flight to France" both require the `get_ticket_price` tool.

- **Parameter Extraction**: The LLM identifies "Paris" as the required argument for the function, even if the user's phrasing is informal or indirect.

## II. Implementing Tools in Python

To equip an LLM with a tool, we follow a three-step process: defining the function, describing it in JSON, and implementing the handling logic.

### Step 1: Defining the Tool Function

This is standard Python code that performs a specific action, such as writing to a file or querying an API.

```python
def record_email_tool(email):
    """Simple tool to record a user's email address."""
    print(f"Tool called to record an email: {email}")
    with open("emails.txt", "a", encoding="utf-8") as f:
        f.write(email + "\n")
    return "Email received"
```

### Step 2: Describing the Tool (JSON Schema)

We must tell the LLM exactly what the tool does and what parameters it requires using a specific JSON format.

```python
record_email_tool_json = {
    "name": "record_email_tool",
    "description": "Use this tool to record that a user provided their email address",
    "parameters": {
        "type": "object",
        "properties": {
            "email": {"type": "string", "description": "The email address of this user"}
        },
        "required": ["email"],
        "additionalProperties": False
    }
}

# The tools list passed to the API
tools = [{"type": "function", "function": record_email_tool_json}]
```

### Step 3: The Orchestration Logic

The developer's software calls the LLM, checks the `finish_reason`, and executes the function if requested.

```python
import json

def chat(message, history):
    # Prepare messages with system prompt and history
    messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}]
    
    # Call the LLM with the 'tools' parameter
    response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)
    
    # Check if the LLM wants to call a tool
    if response.choices[0].finish_reason == "tool_calls":
        message_obj = response.choices[0].message
        tool_call = message_obj.tool_calls[0]
        
        # Extract arguments and call the Python function
        args = json.loads(tool_call.function.arguments)
        result = record_email_tool(args.get("email"))
        
        # Feed the tool result back to the LLM
        messages.append(message_obj)
        messages.append({"role": "tool", "content": result, "tool_call_id": tool_call.id})
        
        # Get the final response from the LLM
        response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)
            
    return response.choices[0].message.content
```

## III. Conceptualizing Autonomy and the Agent Loop

What we call "autonomy" is essentially an LLM making a series of token predictions that represent choices (e.g., `move north` vs. `move south`).

- **Autonomy**: The LLM picks an action based on its training and the provided prompt, without explicit instruction on *which* specific action to take in that moment.

- **The Agent Loop**: The "loop" is not inside the LLM; it is a `while` or `if` statement in the developer's code that repeatedly queries the LLM until the task is complete.

## IV. Conclusion

Tool calling is the "secret sauce" of agentic AI, but it is fundamentally a collaboration between an LLM's reasoning and a developer's code. By providing an LLM with structured descriptions of Python functions, we enable it to understand user intent and autonomously decide which external actions are necessary to achieve a goal.
