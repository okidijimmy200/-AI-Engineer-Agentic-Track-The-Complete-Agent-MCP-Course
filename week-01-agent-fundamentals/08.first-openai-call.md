# Lecture Note: 08. First OpenAI Call (with Code Integration)

## Introduction to Large Language Model (LLM) Interaction

This lecture explores the fundamental principles of interacting with Large Language Models (LLMs) through Application Programming Interfaces (APIs), specifically focusing on OpenAI's models. We will then advance to the concept of **LLM chaining**, a crucial technique for developing more complex, multi-step AI systems, often referred to as **agentic AI**. This note integrates practical code examples directly from the accompanying Jupyter notebook.

## I. Environment Setup and API Key Management

Before making any API calls, it is crucial to set up your environment securely and load your API keys. This ensures that sensitive credentials are not exposed in your code.

### A. Loading Environment Variables

API keys are stored in a `.env` file in the project root. The `dotenv` library is used to load these keys into your Python environment.

```python
from dotenv import load_dotenv

# Load the API keys into environment variables
# If this returns False, ensure your .env file is correctly named and saved.
load_dotenv(override=True)
```

### B. API Key Validation

It is good practice to verify that your API key has been loaded correctly before proceeding.

```python
import os

openai_api_key = os.getenv('OPENAI_API_KEY')

if openai_api_key:
    print(f"OpenAI API Key exists and begins {openai_api_key[:8]}")
else:
    print("OpenAI API Key not set - please head to the troubleshooting guide in the setup folder")
```

### C. Initializing the OpenAI Client

Once the API key is loaded, you can initialize the OpenAI client. Even for other LLM providers compatible with the OpenAI API, this `OpenAI` import is often used, with base URLs configured appropriately (as detailed in Guide 9).

```python
from openai import OpenAI

# Create an instance of the OpenAI class
openai = OpenAI()
```

## II. Making a Basic OpenAI API Call

To effectively communicate with an OpenAI LLM, a structured approach to API calls is essential. The process typically involves preparing messages, invoking the API, and parsing the response.

### A. Message Structure

OpenAI's API expects input in the form of a Python list containing Python dictionaries. Each dictionary represents a distinct message within the conversation, characterized by a `role` and `content`.

- **`role`**: Specifies the sender of the message (e.g., `"user"` for user input, `"system"` for initial instructions, `"assistant"` for LLM responses).

- **`content`**: Contains the actual text of the message.

**Example 2.1: Defining a User Message**

```python
messages = [{"role": "user", "content": "Tell me a fun fact"}]

# Displaying the messages list
messages
```

### B. API Invocation

The `openai.chat.completions.create` method is the primary function for sending these structured messages to the LLM. Key parameters must be provided:

- **`model`**: Identifies the specific LLM to be utilized (e.g., `"gpt-5.4-nano"`). The choice of model depends on the task's complexity and desired performance characteristics.

- **`messages`**: The list of message dictionaries prepared in the previous step.

**Example 2.2: Calling the OpenAI Chat Completions API (GPT 5.4 Nano)**

```python
# This uses GPT 5.4 nano, an incredibly cheap model
response = openai.chat.completions.create(model="gpt-5.4-nano", messages=messages)
```

### C. Response Extraction

Upon receiving a response from the LLM, the generated text content is typically nested within the response object. For most single-turn interactions, it can be accessed as follows:

**Example 2.3: Printing the LLM's Response**

```python
print(response.choices[0].message.content)
```

In the demonstrated lab, an initial call to `gpt-5.4-nano` with the prompt "Tell me a fun fact." yielded a response such as "honey never spoils." This illustrates a successful basic interaction.

## III. Chaining LLM Calls: Towards Agentic AI

While single API calls are useful, the true power of LLMs in complex applications emerges when multiple calls are **chained** together. This involves using the output of one LLM interaction as the input for a subsequent one, enabling multi-step reasoning and problem-solving. This methodology forms a foundational step towards **agentic AI**, where AI systems can autonomously perform sequences of actions.

### A. Illustrative Example: The IQ Question Scenario

The lab provides a clear three-step example of LLM chaining to solve a more intricate problem:

#### Step 1: Generating a Challenging Question

The first step involves an LLM generating a complex question. This demonstrates the LLM's capability to create content based on specific instructions.

- **Objective**: To obtain a hard, challenging question suitable for assessing IQ.

- **Model Used**: `gpt-5.4-mini`.

- **Input Message**: The LLM is prompted with: `"Please propose a hard, challenging question to assess someone's IQ. Respond only with the question."`

**Example 3.1: LLM Generating a Question**

```python
question_prompt = "Please propose a hard, challenging question to assess someone's IQ. Respond only with the question."
messages = [{"role": "user", "content": question_prompt}]

# Ask it - this uses GPT 5.4 mini, still cheap but more powerful than nano
response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages)
question = response.choices[0].message.content
print(question)
```

- **Output**: The LLM generates a question, such as the classic clock hands problem:

   > "A clock has two hands, one of which moves at a constant rate and the other moves at a constant rate, but faster. At 12, they exactly overlap. How many times, if any, will the two hands form a 90 degree angle in a 12 hour period and why?"

#### Step 2: Answering the Generated Question

The question obtained from Step 1 is then passed as input to another LLM call, tasking it with providing an answer.

- **Objective**: To answer the complex question generated in the previous step.

- **Model Used**: `gpt-5.4-mini`.

- **Input Message**: The `content` of the message is the question string obtained from Step 1.

**Example 3.2: LLM Answering the Question**

```python
# Form a new messages list with the generated question
messages = [{"role": "user", "content": question}]
messages

# Ask the model to answer the hard question
response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages)
answer = response.choices[0].message.content
print(answer)

# Displaying the answer as Markdown for better readability
from IPython.display import Markdown, display
display(Markdown(answer))
```

- **Output**: The LLM provides an answer and explanation:

   > "In a 12-hour period, the hands form a 90-degree angle 22 times, and it explains why right there."

#### Step 3: Evaluating the Answer

To ensure the correctness of the LLM's answer, a third LLM call is made. This call takes both the original question and the generated answer as input and is instructed to evaluate the correctness.

- **Objective**: To assess the accuracy of the answer provided by the LLM in Step 2.

- **Model Used**: `gpt-5.4` (a potentially more capable model for evaluation).

- **Input Message Construction**: An f-string is used to combine the question and answer into a single, comprehensive prompt for evaluation.

**Example 3.3: LLM Evaluating the Answer**

```python
message = f"""
Here is a question:
{question}

And here is a possible answer that might be correct or incorrect:
{answer}

Please evaluate if the answer is correct or incorrect.
"""
print(message)

messages = [{"role": "user", "content": message}]
response = openai.chat.completions.create(model="gpt-5.4", messages=messages)
print(response.choices[0].message.content)
```

- **Output**: The evaluating LLM provides feedback:

   > "The answer is correct with one caveat. It is correct if the two hands are the usual minute hand and hour hand of a standard clock."
