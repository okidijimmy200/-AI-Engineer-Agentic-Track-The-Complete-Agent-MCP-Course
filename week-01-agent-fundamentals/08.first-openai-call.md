# Lecture Note: Foundations of LLM Interaction and Agentic AI Chaining

## Introduction to Large Language Model (LLM) Interaction

This lecture explores the fundamental principles of interacting with Large Language Models (LLMs) through Application Programming Interfaces (APIs), specifically focusing on OpenAI's models. We will then advance to the concept of **LLM chaining**, a crucial technique for developing more complex, multi-step AI systems, often referred to as **agentic AI**.

## I. Making a Basic OpenAI API Call

To effectively communicate with an OpenAI LLM, a structured approach to API calls is essential. The process typically involves preparing messages, invoking the API, and parsing the response.

### A. Message Structure

OpenAI's API expects input in the form of a Python list containing Python dictionaries. Each dictionary represents a distinct message within the conversation, characterized by a `role` and `content`.

- **`role`**: Specifies the sender of the message (e.g., `"user"` for user input, `"system"` for initial instructions, `"assistant"` for LLM responses).

- **`content`**: Contains the actual text of the message.

**Example 1.1: Defining a User Message**

```python
messages = [
    {"role": "user", "content": "Tell me a fun fact."}
]
```

### B. API Invocation

The `openai.chat.completions.create` method is the primary function for sending these structured messages to the LLM. Key parameters must be provided:

- **`model`**: Identifies the specific LLM to be utilized (e.g., `"GPT 5.4 nano"`, `"GPT 5.4 mini"`, `"GPT 5.4"`). The choice of model depends on the task's complexity and desired performance characteristics.

- **`messages`**: The list of message dictionaries prepared in the previous step.

**Example 1.2: Calling the OpenAI Chat Completions API**

```python
response = openai.chat.completions.create(
    model="GPT 5.4 nano",
    messages=messages
)
```

### C. Response Extraction

Upon receiving a response from the LLM, the generated text content is typically nested within the response object. For most single-turn interactions, it can be accessed as follows:

**Example 1.3: Printing the LLM's Response**

```python
print(response.choices[0].message.content)
```

In the demonstrated lab, an initial call to `GPT 5.4 nano` with the prompt "Tell me a fun fact." yielded the response: "honey never spoils." This illustrates a successful basic interaction.

## II. Chaining LLM Calls: Towards Agentic AI

While single API calls are useful, the true power of LLMs in complex applications emerges when multiple calls are **chained** together. This involves using the output of one LLM interaction as the input for a subsequent one, enabling multi-step reasoning and problem-solving. This methodology forms a foundational step towards **agentic AI**, where AI systems can autonomously perform sequences of actions.

### A. Illustrative Example: The IQ Question Scenario

The lab provides a clear three-step example of LLM chaining to solve a more intricate problem:

#### Step 1: Generating a Challenging Question

The first step involves an LLM generating a complex question. This demonstrates the LLM's capability to create content based on specific instructions.

- **Objective**: To obtain a hard, challenging question suitable for assessing IQ.

- **Model Used**: `GPT 5.4 mini`.

- **Input Message**: The LLM is prompted with: `"Please propose a hard, challenging question to assess someone's IQ. Respond only with the question."`

- **Output**: The LLM generates a question, such as the classic clock hands problem:

   > "A clock has two hands, one of which moves at a constant rate and the other moves at a constant rate, but faster. At 12, they exactly overlap. How many times, if any, will the two hands form a 90 degree angle in a 12 hour period and why?"

#### Step 2: Answering the Generated Question

The question obtained from Step 1 is then passed as input to another LLM call, tasking it with providing an answer.

- **Objective**: To answer the complex question generated in the previous step.

- **Model Used**: `GPT 5.4 mini`.

- **Input Message**: The `content` of the message is the question string obtained from Step 1.

- **Output**: The LLM provides an answer and explanation:

   > "In a 12-hour period, the hands form a 90-degree angle 22 times, and it explains why right there."

#### Step 3: Evaluating the Answer

To ensure the correctness of the LLM's answer, a third LLM call is made. This call takes both the original question and the generated answer as input and is instructed to evaluate the correctness.

- **Objective**: To assess the accuracy of the answer provided by the LLM in Step 2.

- **Model Used**: `GPT 5.4` (a potentially more capable model for evaluation).

- **Input Message Construction**: An f-string is used to combine the question and answer into a single, comprehensive prompt for evaluation.

   ```python
   message = f"""Here is a question: {question}\nHere is the possible answer: {answer}\nPlease evaluate if the answer is correct or incorrect."""
   messages = [
       {"role": "user", "content": message}
   ]
   ```

- **Output**: The evaluating LLM provides feedback:

   > "The answer is correct with one caveat. It is correct if the two hands are the usual minute hand and hour hand of a standard clock."

### B. Core Principles of LLM Chaining

This demonstration highlights several critical aspects of LLM chaining:

1. **Iterative Problem Decomposition**: Complex problems are broken down into smaller, sequential tasks, each handled by an LLM call.

1. **Dynamic Information Flow**: The output of one LLM serves as dynamic, context-rich input for the next, enabling a continuous flow of information and reasoning.

1. **Modular Specialization**: Different LLMs or distinct prompts can be employed for specialized functions (e.g., generation, summarization, evaluation), optimizing performance for each sub-task.

1. **Foundation for Agentic Behavior**: This chaining mechanism is a fundamental building block for constructing agentic AI systems capable of autonomous planning, execution, and self-correction based on intermediate results.
