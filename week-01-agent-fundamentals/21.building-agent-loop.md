# Lecture Note: 21. Building Agent Loop (with Code Integration)

## Introduction

In this lecture, we reach a critical milestone: the implementation of an **Agent Loop** from scratch. We will strip away the "magic" of agentic AI to reveal its core components: a series of Large Language Model (LLM) calls, structured JSON data, and basic Python control flow (the `while` loop). By manually constructing this loop, we gain a concrete understanding of how autonomy is achieved in practice.

## I. The Anatomy of a Tool Call

Implementing a tool call is a "janky" process of plumbing that bridges the gap between the LLM's token generation and the execution of Python code.

### A. The Basic Workflow

1. **Orchestration**: Send the user message and tool descriptions (JSON schema) to the LLM.

1. **Inspection**: Check the `finish_reason` of the response. If it is `tool_calls`, the LLM is requesting an action.

1. **Execution**: The developer's code parses the requested tool and arguments, calls the corresponding Python function, and captures the result.

1. **Feedback**: The tool result is appended to the message history, and the LLM is called again to generate a final response based on that new information.

## II. Transitioning from `if` to `while`: Creating the Loop

The fundamental difference between a single tool call and an autonomous agent is the **Loop**.

### A. The Single-Tool Limitation (`if` statement)

In a basic implementation, an `if` statement allows the LLM to call a tool exactly once. If the task requires multiple steps (e.g., recording three different emails), the system fails or provides an incomplete result because it lacks the mechanism to go back and ask, "What next?"

### B. The Autonomous Agent (`while` loop)

By replacing the `if` statement with a `while` loop, we create a system that repeatedly queries the LLM until the model determines that no further actions are required (i.e., the `finish_reason` is no longer `tool_calls`).

**Example 2.1: The Agentic ****`chat`**** Function (While Loop)**

```python
import json

def chat(message, history):
    # 1. Prepare messages with system prompt and history
    messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}]
    
    # 2. Initial LLM call with tools
    response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)
    
    # 3. The Agent Loop: Continue while the LLM wants to call tools
    while response.choices[0].finish_reason == "tool_calls":
        message_obj = response.choices[0].message
        messages.append(message_obj)
        
        # 4. Handle potentially multiple concurrent tool calls
        for tool_call in message_obj.tool_calls:
            # Extract arguments (e.g., email)
            args = json.loads(tool_call.function.arguments)
            
            # Manually call our Python function
            result = record_email_tool(args.get("email"))
            
            # Append the result to the history with the matching tool_call_id
            messages.append({
                "role": "tool", 
                "content": result, 
                "tool_call_id": tool_call.id
            })
        
        # 5. Re-query the LLM with the updated history
        response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)
            
    # 6. Return the final content once the loop breaks
    return response.choices[0].message.content
```

## III. Handling Complexity: For Loops and Concurrent Calls

Modern LLMs are capable of requesting multiple tool calls in a single response (e.g., "Record these three emails").

- **The Technicality**: An inner `for` loop is required to iterate through the `tool_calls` list within each iteration of the `while` loop.

- **The Result**: This allows the agent to handle complex, multi-part goals efficiently, calling tools in parallel or sequence as dictated by the LLM's reasoning.

## IV. The "Illusion of Autonomy" Revisited

Seeing the code reveals that autonomy is simply a design pattern:

1. **JSON Schema**: Tells the LLM what it *can* do.

1. **While Loop**: Gives the LLM the *opportunity* to act repeatedly.

1. **Developer Code**: Does the *actual* work of executing functions.

While this manual implementation is "hacky," it is exactly what agent frameworks like CrewAI or OpenAI SDK do under the hood. Understanding this plumbing is the "rite of passage" for any AI engineer.

## V. Conclusion

We have successfully constructed an autonomous agent loop from first principles. By combining a `while` loop with tool calling, our Digital Twin can now independently decide to record multiple emails to a file until its goal is achieved. This foundation sets the stage for more sophisticated agentic behaviors, such as context engineering and modular refactoring, which we will explore in the coming lectures.
