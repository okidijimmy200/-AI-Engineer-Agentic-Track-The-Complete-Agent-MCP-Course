# Lecture Note: 20. Gradio Chat UI (with Code Integration)

## Introduction

In this lecture, we transition from backend data processing to building an interactive interface for our **Digital Twin**. We will construct a sophisticated system prompt that defines the agent's persona and rules, package the LLM interaction into a reusable `chat` function, and finally, deploy a functional user interface using **Gradio**. This stage is crucial for testing how the agent handles context and persona in real-time dialogue.

## I. Constructing the Digital Twin System Prompt

The system prompt is the "DNA" of the agent, providing the necessary framing and context for every interaction. A well-structured prompt often uses Markdown headings to separate different functional sections.

### A. The Three-Section Architecture

1. **Your Role**: Defines the persona (e.g., "You are a digital twin") and specifies the target audience (visitors of the website).

1. **Context**: Injects the raw data extracted from the LinkedIn PDF and the personal summary.

1. **Rules**: Establishes behavioral boundaries, such as staying in character, being professional, and avoiding non-career-related topics.

**Example 1.1: The Digital Twin System Prompt**

```python
system_prompt = f"""
# Your Role
You are a digital twin running on a website, chatting with visitors. 
You represent the person whose website you are on and answer questions 
related to their career, background, skills, and experience.

Here are the details of the person you are representing:
{summary_text}

# Context
Here is a summary of the person's LinkedIn profile:
{linkedin_text}

# Rules
- Engage professionally, as if talking to a potential client or employer.
- Avoid answering questions not related to career or background.
- IMPORTANT: If you don't know the answer, say so. Never make up an answer.
"""
```

## II. The `chat` Function: Packaging the Agent

To interact with a UI framework like Gradio, we must package the LLM call into a standard function that manages the **Conversation History**.

### A. Managing State and History

The `chat` function takes two arguments: the new `message` from the user and the `history` (the list of previous message dictionaries). It constructs a complete sequence starting with the `system_prompt`, followed by the `history`, and ending with the new `user` message.

**Example 2.1: The ****`chat`**** Function Implementation**

```python
def chat(message, history):
    # Construct the full message list for the API call
    messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}]
    
    # Call the LLM (GPT 5.4 Mini or Nano)
    response = openai.chat.completions.create(
        model="gpt-5.4-mini", 
        messages=messages
    )
    
    return response.choices[0].message.content
```

> **Technical Tip**: If using non-OpenAI models (like Grok), the `history` object might contain extra fields that cause API errors. Use the following line to "scrub" the history:`history = [{"role": h["role"], "content": h["content"]} for h in history]`

## III. Deploying the Gradio User Interface

**Gradio** is an open-source Python library that allows for the rapid creation of UIs for machine learning models. It handles the complexity of the web interface, allowing the developer to focus on the logic.

### A. The Gradio `ChatInterface`

Gradio provides a specialized `ChatInterface` class. All it requires is a reference to a callback function (like our `chat` function) that follows the `(message, history)` signature.

**Example 3.1: Launching the UI**

```python
import gradio as gr

# Launch the interface in the browser
gr.ChatInterface(chat).launch(inbrowser=True)
```

### B. How it Works Under the Hood

When a user types a message and presses enter:

1. Gradio captures the text.

1. Gradio aggregates the entire conversation history from the UI widget.

1. Gradio calls the `chat` function with the new message and the accumulated history.

1. The `chat` function queries the LLM and returns the response.

1. Gradio displays the response in the chat window.

## IV. Iteration and Prompt Engineering

Testing the Digital Twin often reveals areas for improvement. For instance, if the agent answers questions about personal topics despite rules to avoid them, the developer must iterate on the **System Prompt**.

- **Positive Reinforcement**: Prompts often work better when they tell the LLM what *to* do rather than what *not* to do.

- **Conflicting Data**: If the summary contains personal details (like a dislike for cheese), the LLM may prioritize that information even if the rules say "only career-related."
