# Lecture Note: 27. Deploy HuggingFace

## Introduction

In this final lecture of the module, we move our Digital Twin from the local development environment to a live, production-ready status on the internet. We use **Hugging Face Spaces**, a powerful platform for hosting machine learning applications. By the end of this session, your autonomous agent will be accessible via a public URL, capable of interacting with users worldwide and sending real-time notifications to your mobile device.

## I. The Deployment Platform: Hugging Face Spaces

Hugging Face is the premier hub for open-source AI. Their "Spaces" feature allows developers to host and share applications for free.

- **Gradio Support**: Spaces has native, first-class support for Gradio, making it the ideal choice for our Digital Twin.

- **Lifecycle**: Free-tier spaces automatically "sleep" when inactive to save resources and wake up instantly when accessed.

- **Embeddability**: Once deployed, a space can be embedded directly into a personal portfolio or business website.

## II. Authentication and Setup

Deploying to Hugging Face requires secure authentication via access tokens.

### A. Creating an Access Token

1. Navigate to `huggingface.co` and sign up or log in.

1. Go to **Settings > Access Tokens**.

1. Create a new token with **Write** permissions (crucial for creating new spaces).

1. Store this token in your local `.env` file as `HF_TOKEN`.

### B. CLI Authentication

Using the **UV** tool for a clean environment, log in via the terminal:

```bash
uvx hf auth login --token <YOUR_TOKEN>
```

Verify the login with `uvx hf auth whoami`.

## III. The Deployment Process

Gradio provides a remarkably simple deployment command that handles the heavy lifting of containerization and uploading.

### A. The Deployment Command

From within the `twin/` directory, run:

```bash
uv run gradio deploy
```

### B. Configuration Steps (The "Enter" Strategy)

During the deployment process, the CLI will prompt for several configurations. For our project, we accept the defaults for all:

1. **App Title**: `twin`

1. **Gradio Module**: `app.py`

1. **Hardware**: `CPU basic` (Free tier)

1. **Secrets**: Skip this step during the CLI process (we will add them manually for reliability).

1. **GitHub Actions**: `No`

## IV. Managing Production Secrets

**Security Warning**: Never upload your `.env` file to Hugging Face. Spaces are public repositories; anyone can see the code and files. Sensitive keys must be added as **Secrets** in the Hugging Face dashboard.

### A. Adding Secrets Manually

1. Go to your Space on Hugging Face and navigate to **Settings**.

1. Scroll to **Variables and Secrets**.

1. Add the following as **New Secrets** (not variables):
  - `OPENAI_API_KEY`: Your OpenAI credentials.
  - `PUSHOVER_USER`: Your Pushover user key (starts with `U`).
  - `PUSHOVER_TOKEN`: Your Pushover application token (starts with `A`).

### B. Restarting the Space

After adding secrets, you must **Restart** the space to inject the new environment variables into the running container.

## V. Final Verification

Once the space is "Running," access the public URL.

1. **Engagement**: Test the chat interface with professional questions.

1. **Agency**: Ask an out-of-scope question (e.g., "What's your favorite food?") to verify that the `record_unknown_question` tool triggers a push notification from the production server.

1. **Lead Gen**: Provide an email address to verify the `record_interest_tool` functions correctly in the wild.
