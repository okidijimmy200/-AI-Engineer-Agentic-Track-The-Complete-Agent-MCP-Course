# Lecture Note: 24. Multiple Tool Calls (with Code Integration)

## Introduction

As we scale our Digital Twin to handle multiple tools, the orchestration logic must evolve. In this lecture, we transition from hardcoded tool handling to a more dynamic and elegant approach. We explore how to manage multiple incoming tool requests from an LLM and how to map those requests to actual Python functions efficiently using Python's built-in capabilities.

## I. The Challenge of Scaling Tool Handling

In a single-tool scenario, a simple `if` statement is sufficient. However, as the number of tools grows (e.g., adding `record_interest_tool` and `record_unknown_question`), a manual `if/elif` chain becomes "ugly," repetitive, and difficult to maintain.

### A. The "Ugly" Manual Approach

```python
def handle_tool_calls_manual(tool_calls):
    results = []
    for tool_call in tool_calls:
        name = tool_call.function.name
        args = json.loads(tool_call.function.arguments)
        
        if name == "record_interest_tool":
            result = record_interest_tool(**args)
        elif name == "record_unknown_question":
            result = record_unknown_question(**args)
        # ... more elifs ...
        
        results.append({"role": "tool", "content": result, "tool_call_id": tool_call.id})
    return results
```

## II. Dynamic Function Mapping with `globals()`

To avoid the "clunky" if-statement, we can leverage the `globals()` built-in function in Python. `globals()` returns a dictionary representing the current global symbol table, allowing us to look up and execute functions by their string names.

### A. The Concept

If the LLM requests a tool named `"record_unknown_question"`, we can look up that exact string in the `globals()` dictionary to get a reference to the actual Python function.

**Example 2.1: Manual Global Lookup**

```python
# Look up the function by name
func = globals().get("record_unknown_question")

# Execute the function with arguments
if func:
    func(question="Why is the sky blue?")
```

### B. The Elegant `handle_tool_calls` Implementation

By using this lookup, we can create a single, generic function that handles any number of tools without needing to be updated every time a new tool is added.

```python
def handle_tool_calls(tool_calls):
    results = []
    for tool_call in tool_calls:
        tool_name = tool_call.function.name
        arguments = json.loads(tool_call.function.arguments)
        
        # Dynamic lookup in the global namespace
        tool_function = globals().get(tool_name)
        
        if tool_function:
            # Call the function with unpacked arguments
            result = tool_function(**arguments)
        else:
            result = f"Error: Tool '{tool_name}' not found."
            
        results.append({
            "role": "tool",
            "content": json.dumps(result),
            "tool_call_id": tool_call.id
        })
    return results
```

## III. Safety and Security Considerations

While using `globals()` is elegant, it introduces a significant **security risk**.

- **The Risk**: By granting the LLM access to any function in the global namespace, you are essentially trusting it not to call sensitive or dangerous functions (e.g., `exec`, `eval`, or internal system utilities) that were never intended to be tools.

- **The Production Solution**: In a production environment, you should use a dedicated **registry** or dictionary that explicitly maps only the allowed tool names to their respective functions, rather than exposing the entire global scope.

## IV. Finalizing the Agent Loop

With the dynamic handler in place, our agent loop becomes concise and robust. It can now handle multiple tools called sequentially or concurrently in a single turn.

```python
def chat(message, history):
    messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}]
    
    response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)

    return response.choices[0].message.content
```
