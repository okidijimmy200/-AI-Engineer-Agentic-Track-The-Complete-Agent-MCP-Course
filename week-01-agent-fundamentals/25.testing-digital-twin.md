## I. Context Engineering: Refining the System Prompt

The final system prompt requires careful crafting to ensure the agent adheres to its persona while correctly utilizing its new tools.

### A. Positive Framing and Reinforcement

- **Avoid Negatives**: Instead of saying "Don't answer unrelated questions," we frame it positively: "If the user asks about something unrelated, steer the conversation back to professional topics."

- **Tool-Specific Instructions**: While tools have their own descriptions, repeating key triggers in the system prompt (e.g., "If you don't know the answer, use your tool to record the question") helps bias the model toward the desired behavior.

**Example 1.1: Final Digital Twin System Prompt**

```python
system_prompt = f"""
# Your Role
You are a digital twin of the person whose website you are on. 
Answer questions about their career, background, and skills.

# Details of the Person
{summary_text}

# Context
LinkedIn Summary: {linkedin_text}

# Rules
- Be professional and engaging.
- Steer unrelated questions back to professional topics.
- If you don't know an answer, use the 'record_unknown_question' tool.
- If a user wants to connect, use the 'record_interest_tool'.
"""
```

## II. The Final Agent Loop Implementation

The final `chat` function brings together the `while` loop for autonomy and the `handle_tool_calls` function for dynamic execution.

### A. The Complete Workflow

1. **Initial Call**: The LLM is provided with the context, history, and tools.

1. **The Loop**: As long as the `finish_reason` is `tool_calls`, the agent remains in the loop.

1. **Dynamic Execution**: `handle_tool_calls` maps the LLM's request to the actual Python function (e.g., sending a Pushover notification).

1. **History Extension**: The `messages.extend(results)` call is crucial, as it adds all tool responses back into the context for the LLM's next reasoning step.

**Example 2.1: The Final Agentic Chat Function**

```python
def chat(message, history):
    messages = [{"role": "system", "content": system_prompt}] + history + [{"role": "user", "content": message}]
    
    # Initial reasoning step
    response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)
    
    # The Agent Loop
    while response.choices[0].finish_reason == "tool_calls":
        message_obj = response.choices[0].message
        messages.append(message_obj)
        
        # Process multiple tool calls dynamically
        tool_results = handle_tool_calls(message_obj.tool_calls)
        messages.extend(tool_results)
        
        # Re-query the LLM with the results
        response = openai.chat.completions.create(model="gpt-5.4-mini", messages=messages, tools=tools)
            
    return response.choices[0].message.content
```

## III. Verification and Testing Scenarios

Testing the Digital Twin involves verifying its ability to handle both professional queries and out-of-scope interactions.

### A. Scenario 1: Out-of-Scope Handling

- **User Query**: "Who is your favorite musician?"

- **Agent Action**: The agent recognizes the question is unrelated to the career context. It triggers the `record_unknown_question` tool (sending a push notification to the developer) and politely informs the user that the topic is outside its professional scope.

### B. Scenario 2: Lead Generation and Tool Execution

- **User Query**: "I'd like to get in touch. My email is [test@example.com](mailto:test@example.com)."

- **Agent Action**: The agent identifies the intent to connect, extracts the email address, and calls the `record_interest_tool`. The developer receives a real-time alert via Pushover with the user's details.

## IV. Observations on Autonomy

The use of push notifications provides a tangible sense of **agency**. When the phone lights up with a notification, it confirms that the agent has independently made a decision to act upon the user's input. This interaction bridges the gap between digital reasoning and physical-world action.
