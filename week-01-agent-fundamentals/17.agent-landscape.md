# Lecture Note: 17. Agent Landscape

## Introduction

Welcome to Week 1, Day 4. Today marks a pivotal moment in the course as we transition from theoretical definitions to the practical implementation of AI agents. Having mastered the orchestration of multiple Large Language Model (LLM) calls, we now turn our attention to the broader ecosystem of agentic AI. This lecture provides a comprehensive overview of the current agent landscape, categorizing the diverse offerings into a coherent framework to help you navigate this rapidly evolving—and often overhyped—field.

## I. The Four Pillars of the Agent Landscape

The agentic AI ecosystem can be broadly divided into four distinct categories, each serving different users and needs.

| Category | Description | Key Examples |
| --- | --- | --- |
| **AI Builders** | Platforms that allow both technical and non-technical users to build agent solutions, often via drag-and-drop interfaces. | N8N, 11Labs (Voice), OpenAI AgentBuilder, CrewAI Studio |
| **Agent Products** | End-user applications that utilize agents internally to perform specific tasks or provide services. | Claude Code, Cowork (Anthropic), OpenClaude, Claude Design |
| **Agent Runtimes** | Platforms specialized for executing, hosting, and managing the interaction of agents "in the wild." | AWS Bedrock Agent Core, Vertex AI Agent Engine, AWS Lambda (General) |
| **Agent Frameworks** | Libraries and software tools that technical people use to develop AI agents quickly. | OpenAI Agents SDK, CrewAI, LangGraph/LangChain, Google ADK |

## II. Deconstructing Agent Frameworks

Agent frameworks are essentially **abstraction layers**. They provide utility and helper code to handle repetitive tasks associated with building complex agentic systems.

### A. Core Functions of a Framework

1. **Orchestration**: Simplifying the process of chaining and gluing together multiple LLM calls.

1. **Tool Calling**: Managing the "janky" manual process of giving LLMs external capabilities (e.g., looking up data). This often includes support for the **Model Context Protocol (MCP)**, a standard for connecting to third-party tools.

1. **Input/Output Handling**: Managing sophisticated techniques like **Structured Outputs**, where an LLM is prompted to generate JSON that is then automatically converted into a Python object for programmatic use.

### B. The Spectrum of Frameworks

Frameworks range from lightweight to highly opinionated:

- **Lightweight (Low Abstraction)**: Provides maximum control but requires more manual coding.
  - *Examples*: OpenAI Agents SDK, Google ADK, AWS Strands Agents.

- **Opinionated (High Abstraction)**: Prescribes a specific way of working, often "batteries included" with built-in functionality.
  - *Examples*: **CrewAI** (very popular for rapid development) and **LangGraph/LangChain** (enterprise-grade, structured, and repeatable).

## III. The "No Framework" Philosophy

A critical takeaway of this lecture is that **building an agent does not require a framework**. In fact, following the advice of industry leaders like Anthropic, we recommend starting without one.

- **Why start without a framework?** It provides a clear, tangible, and concrete understanding of how LLM calls, tools, and loops interact without the "black box" of an abstraction layer.

- **The Rite of Passage**: In this module, we will "hand-roll" our own agent loop from first principles. While the process may feel "janky" compared to using a framework, it is an essential step in mastering the underlying mechanics of agentic AI.

## IV. Conclusion

The agent landscape is vast and immature, filled with overlapping terminology and hype. By understanding the distinctions between builders, products, runtimes, and frameworks, you are better equipped to choose the right tools for your specific needs. As we move forward, we will explore each of the major frameworks in detail, but our immediate focus remains on building a robust foundation by constructing our own agentic systems from the ground up.
